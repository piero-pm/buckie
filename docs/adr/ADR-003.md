# ADR-003: Client-side KDF and encryption library

## Context

ADR-002 requires deriving a data key from a user passphrase in the browser and
encrypting/decrypting client-side. This ADR fixes the primitives so behavior is
durable and reviewable. It is a security decision and must be human-approved.

## Options

- KDF: Argon2id (memory-hard, resists GPU cracking) vs PBKDF2 (available in native
  WebCrypto, weaker against dedicated hardware) vs scrypt.
- Symmetric cipher: AES-256-GCM (native WebCrypto, authenticated) vs XChaCha20-
  Poly1305 (via libsodium, nonce-misuse friendlier).
- Library: WebCrypto (built-in, no Argon2) vs libsodium.js / hash-wasm (Argon2id in
  WASM) vs argon2-browser.

## Decision (recommended)

- KDF: Argon2id via a maintained WASM library (hash-wasm or libsodium.js), with
  per-user random salt stored server-side alongside ciphertext, and parameters tuned
  to ~1s on a typical device (documented, revisitable).
- Cipher: AES-256-GCM via native WebCrypto with a random 96-bit nonce per record.
- Derived key kept as a non-extractable CryptoKey and cached in-memory plus IndexedDB
  where the platform allows non-extractable persistence; passphrase re-entry only on
  a new device or after cache eviction.

## Consequences

- One WASM dependency (Argon2id) plus native WebCrypto; small bundle cost, no server
  crypto for user data. Parameters and library are the ADR-002 future-revisit point.
- Salt and KDF parameters are non-secret and stored with the ciphertext so any device
  can re-derive the key from the passphrase.
- Wrong passphrase yields a GCM authentication failure, giving a clean "wrong
  passphrase" signal without revealing plaintext.
- Frontend crypto unit tests (derive, encrypt, decrypt, wrong-passphrase, tamper)
  are required (brief §5).

Human must approve Argon2id + AES-256-GCM and the WASM dependency. Recommendation
only; awaiting explicit human approval.
