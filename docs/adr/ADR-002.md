# ADR-002: Client-side, passphrase-derived confidentiality (host-blind)

## Context

BR-CONF-1 requires that no user and no host operator can casually read another
user's financial data. On 2026-08-10 the human approved host-blind confidentiality:
the server stores only ciphertext and never holds the means to decrypt it. This
supersedes the earlier at-rest / server-managed-key options once held in this ADR.

## Decision (recommended)

- Login stays passwordless email-OTP; it governs session and identity ONLY and is
  never used to derive a data key.
- Confidentiality uses a SEPARATE user encryption passphrase (>= 12 alphanumeric
  chars) entered in the browser and stretched by a strong KDF (Argon2id) to a data
  key. Encryption and decryption happen client-side; only ciphertext reaches the
  server. The server NEVER receives the passphrase or the derived key.
- The derived key is cached on the device (non-extractable where possible), so the
  passphrase is re-entered only on a new device. The user is advised to store the
  passphrase in a password manager; email is an accepted lower-security fallback.
- No server-side recovery: a lost passphrase means unrecoverable data.
- KDF and library specifics are recorded in [ADR-003](ADR-003.md).

## Consequences and routing

- Honest privacy promise: "only the user, holding their passphrase, can read their
  data; the operator cannot." The host is a blind ciphertext store plus auth/session.
- Domain logic that needs plaintext moves client-side: validation, duplicate
  detection, recurring expansion, and all dashboard aggregation (see brief §3).
  Deterministic/searchable encryption is rejected as it would weaken this promise.
- Increased client complexity is an accepted tradeoff to keep hosting cheap
  (SQLite + one VPS, ADR-001 unchanged).
- Passphrase loss = data loss, stated plainly to the user at setup.
- Revisit marker: the human noted the encryption METHOD may change later; Phase 1 is
  built around this decision, but the KDF/library and key-caching are the intended
  future-revisit points.

Human must approve: the host-blind model, passphrase-loss = data-loss acceptance,
and the >= 12-char passphrase policy. Recommendation only; awaiting approval.
